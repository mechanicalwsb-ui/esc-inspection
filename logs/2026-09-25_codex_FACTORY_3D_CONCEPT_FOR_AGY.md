**“เห็นทั้งโรงงานในภาพเดียว แล้วแตะไปยังจุดที่ต้องดูแล”**

## 2. วิธีใช้ภาพอ้างอิง

### ภาพที่ 1: หน้าระบบปัจจุบัน

ใช้เป็นแนวทางรักษาอัตลักษณ์ ESC ได้แก่ sidebar เขียวเข้ม ปุ่มเขียวสด โลโก้องค์กร ฟอนต์ไทย และพื้นหน้าจอสว่าง วางเมนูใหม่ใต้ “แดชบอร์ดศูนย์กลาง” ให้ผู้ใช้สลับระหว่างตัวเลขสรุปกับภาพพื้นที่ได้

### ภาพที่ 2: ภาพถ่ายโรงงานมุมสูง

ใช้เป็นหลักในการกำหนดรูปทรงและความสัมพันธ์เชิงพื้นที่ ไม่ตีความว่าภาพเดียวบอกหน้าที่อาคาร ตำแหน่งเครื่องจักร ขนาดจริง หรือทิศเหนือได้ครบ

| สิ่งที่มองเห็นในภาพ | สิ่งที่ควรรักษาในโมเดล | ชื่อชั่วคราวใน UI |
| --- | --- | --- |
| ถนนจากด้านล่างกลางภาพเข้ามาแล้วแยกซ้าย–ขวา | ให้เป็นเส้นนำสายตาจากหน้าโมเดลเข้าสู่โรงงาน | ทางเข้าและถนนหลัก |
| อาคารทรงเด่นสีแดงอยู่หน้าลาน | รักษาสีแดงและตำแหน่งด้านหน้า เป็นจุดจำหลัก | อาคารด้านหน้า |
| บ่อน้ำรูปทรงมนด้านหน้าซ้ายของถนน | น้ำสีฟ้าอมเขียว ขอบหญ้าและต้นไม้ล้อม | บ่อน้ำด้านหน้า |
| อาคารเตี้ยหลังคาขาวด้านหน้าซ้าย | กลุ่มอาคารย่อยแยกจากโรงงานหลัก มีถนนเชื่อม | กลุ่มอาคารด้านหน้าซ้าย |
| อาคารสีขาวขนาดใหญ่หลายหลังทางซ้ายและกลาง | แสดงหลายระดับความสูง หลังคาลาด และทางเชื่อม | กลุ่มอาคารผลิต A–C |
| ถังแนวตั้งสีฟ้าอ่อนและปล่องในบริเวณอาคารซ้าย | ใช้เป็นรายละเอียดประกอบที่ช่วยให้คล้ายภาพ | ถังและโครงสร้างแนวตั้ง |
| ลานคอนกรีตกว้างกลางภาพ | เว้นพื้นที่ว่างจริง อย่าเติมอาคารจนแน่น | ลานกลางโรงงาน |
| บ่อสี่เหลี่ยมหลายช่องทางขวา | จัดเป็นกลุ่ม มีคันบ่อและทางเดินคั่น | กลุ่มบ่อด้านขวา |
| โครงสร้างยาวสีฟ้า/เขียวด้านหลัง | เก็บเส้นขอบและระดับความสูงเป็นฉากหลัง | อาคารและโครงสร้างด้านหลัง |
| แนวต้นไม้ล้อมโรงงาน ถนนรอบพื้นที่ และภูเขาไกล | ใช้ต้นไม้จัดจังหวะและภูเขาทรงเรียบสีจาง | พื้นที่สีเขียวและฉากหลัง |

## 3. ทิศทางงานภาพ: Soft Cartoon Industrial Diorama

### อารมณ์และรูปลักษณ์

- โรงงานสะอาด มีชีวิต และเป็นมิตร เหมือนโมเดลจำลองคุณภาพดีสำหรับศูนย์ควบคุม
- รูปทรงอาคารอ่านง่าย หลังคามีความหนา ขอบนุ่มเล็กน้อย ผนังมีเงาและช่องเปิดพอประมาณ
- ต้นไม้เป็นพุ่มกลมหรือทรงกรวยหลายเฉด มีลำต้นสั้น จัดเป็นแนวตามภาพจริง
- ถนนสีเทาอุ่น มีเส้นจราจรเล็กน้อย ขอบทางชัด และรถขนาดเล็กจำนวนน้อยเพื่อเทียบสเกล
- น้ำสีเขียวอมฟ้า มีไฮไลต์บาง ๆ โดยไม่จำเป็นต้องจำลองคลื่นหรือการสะท้อนแบบสมจริง
- โมเดลวางบนฐานแผ่นดินขอบมนบาง ๆ สีดินอ่อน มีเงารองฐาน ทำให้รู้สึกเป็นของจำลอง
- ฉากหลังสีครีมอมเขียว ไล่ไปฟ้าอ่อน ภูเขาไกลลดรายละเอียดและความเข้ม
- ใช้แสงกลางวันอุ่นจากด้านซ้ายบน เงานุ่มไปทิศเดียวกัน ลดผิวโลหะมันวาวจัด
- ให้ภาพโรงงานเป็นพระเอก: หลีกเลี่ยงการ์ดใหญ่ ป้ายจำนวนมาก หรือเอฟเฟกต์เรืองแสงที่บดบังรูปทรง

### มุมกล้องและองค์ประกอบ

- มุมเริ่มต้น: มองเฉียงจากทางเข้าด้านหน้า ก้มประมาณ 35–45 องศา ปรับจนเห็นถนนหน้าโรงงานและหลังคาอาคารครบ
- ใช้มุมมองแบบ orthographic เพื่อให้ความรู้สึกโมเดลย่อส่วนและรักษาขนาดวัตถุบนจอ
- จัดโรงงานอยู่กลาง viewport มีขอบว่างประมาณ 8–12% เผื่อ label และปุ่มควบคุม
- ให้กลุ่มอาคารสูงอยู่ซ้ายบน ลานกลางอยู่กลางภาพ กลุ่มบ่ออยู่ขวาบน อาคารแดงอยู่ด้านหน้ากลาง
- เปิดหน้าแล้วเห็นทั้งโรงงานทันที ไม่เริ่มต้นด้วยมุมใกล้เครื่องจักร
- ไม่หมุนกล้องเองโดยค่าเริ่มต้น; การหมุนโชว์โมเดลเป็นปุ่มเสริมที่เปิดเองได้ภายหลัง
- จำกัดการก้มและซูมเพื่อไม่ให้หลุดใต้พื้นหรือเข้าไปในอาคาร มีปุ่ม “กลับมุมเริ่มต้น” เสมอ

## 4. แผนผังเชิงแนวคิดสำหรับขึ้นโมเดล

กำหนดพื้นที่ออกแบบ 100 × 100 หน่วย โดย X เพิ่มไปด้านขวา, Z เพิ่มไปด้านหลัง, Y เป็นความสูง ตัวเลขนี้เป็นสัดส่วนสมมติสำหรับจัดฉาก ไม่ใช่เมตรหรือพิกัดสำรวจ

   ┌───────────────────────────────────────────┐
   │ อาคารยาวและโครงสร้างสีฟ้า/เขียวด้านหลัง   │
   │                                           │
   │ กลุ่มอาคารผลิต A–C       กลุ่มบ่อสี่เหลี่ยม │
   │ ถัง/ปล่อง/ทางเชื่อม       และทางเดินคั่น    │
   │                                           │
   │ อาคารย่อย        ลานกลางกว้าง             │
   │                       อาคารแดงด้านหน้า    │
   │ อาคารหน้าซ้าย ─── ถนนแยกซ้าย–ขวา ──────  │
   │             บ่อน้ำมน  │                   │

                           ทางเข้า

## 5. หน้าจอที่ผู้ใช้จะเห็น

### Desktop

1. sidebar เดิม เพิ่มเมนู “ภาพรวมโรงงาน 3D” ใต้แดชบอร์ด
2. แถวหัวหน้า: ชื่อหน้า, ช่องค้นหาเครื่องจักร, ตัวกรองแผนก, ปุ่มรีเฟรช
3. แถบสรุปขนาดกะทัดรัด: เครื่องจักรทั้งหมด / ผิดปกติ / เฝ้าระวัง / งานซ่อมค้าง
4. พื้นที่โมเดลใช้พื้นที่หลักประมาณ 70–80% ของส่วนเนื้อหา ไม่มีตารางขนาดใหญ่ขวางหน้าโมเดล
5. ด้านล่างโมเดล: คำอธิบายสีและเวลาอัปเดตข้อมูลล่าสุด
6. มุมขวาบนโมเดล: กลับมุมเริ่มต้น, มุมบน, ซูมเข้า/ออก, เต็มจอ
7. เมื่อเลือกโซน จึงเปิดแผงรายละเอียดด้านขวากว้างประมาณ 320–360 px และปรับกรอบภาพให้ยังเห็นจุดที่เลือก

### iPad / จอสัมผัส

- แนวนอน: โมเดลเป็นพื้นที่หลัก แผงรายละเอียดเลื่อนเปิดจากขวา
- แนวตั้ง: โมเดลด้านบน รายละเอียดเป็น bottom sheet ที่ย่อ/ขยายได้
- ปุ่มสำคัญมีพื้นที่สัมผัสอย่างน้อย 48 px และมุ่งใช้ 56 px ในโหมดหน้างานตามแผน v2
- แตะเพื่อเลือก, ลากหนึ่งนิ้วหมุน, สองนิ้วเลื่อนและ pinch เพื่อซูม พร้อมปุ่มควบคุมสำหรับผู้ที่ไม่ถนัด gesture
- แยกการแตะกับการลากด้วยระยะเคลื่อนที่ขั้นต่ำ เพื่อไม่เปิดอาคารโดยไม่ตั้งใจขณะหมุน
- ไม่มีฟังก์ชันที่ต้อง hover เท่านั้น ใช้แตะและคีย์บอร์ดเข้าถึงข้อมูลเดียวกันได้

## 6. ลำดับการสำรวจ: โรงงาน → โซน → เครื่องจักร → งานตรวจ

### ระดับ 1: ภาพรวมโรงงาน

แสดง label โซนเพียง 5–8 จุด ไม่แสดงชื่อเครื่องทุกเครื่องพร้อมกัน ป้ายแต่ละโซนมีชื่อสั้นและจำนวนเครื่องผิดปกติ/เฝ้าระวัง เมื่อไม่มีตำแหน่งเครื่องจักรที่ยืนยันแล้วให้แสดง “ยังไม่ผูกเครื่องจักร” แทนสถานะปกติ

### ระดับ 2: เลือกโซน

แตะอาคารหรือป้าย → ขอบเขตโซนสว่างขึ้น → กล้องขยับเข้าใกล้อย่างนุ่มนวล → เปิดแผงแสดง:

- ชื่อพื้นที่และข้อความ “ตำแหน่งอ้างอิง” หากยังไม่ยืนยัน
- จำนวนเครื่องจักรที่ตรงกับตัวกรองและจำนวนเครื่องที่ยังไม่มีข้อมูลตรวจ
- สถานะและวันเวลาการตรวจล่าสุด
- รายการเครื่องจักรในโซน พร้อมรหัส ชื่อ และสถานะ
- งานซ่อมที่ยังเปิดอยู่ของโซน

อย่าเปลี่ยนหลังคาทั้งโรงงานเป็นสีแดง ใช้เส้นขอบ ป้าย หรือวงแหวนเล็ก ๆ เพื่อรักษาความสวยของภาพ

### ระดับ 3: เลือกเครื่องจักร

รุ่นแรกแสดงเครื่องผ่านรายการในแผงรายละเอียดและ marker เฉพาะตำแหน่งที่มี mapping แล้ว รุ่นถัดไปค่อยเพิ่มมุมแยกชั้น/ยกหลังคาเมื่อมีข้อมูลภายในอาคาร ไม่สร้างตำแหน่งเครื่องในอาคารจากการเดาภาพถ่ายภายนอก

การ์ดเครื่องจักรควรแสดงรหัส ชื่อ แผนก พื้นที่ สถานะเดินเครื่อง ผลตรวจล่าสุด และจำนวนงานซ่อมค้าง พร้อมปุ่ม:

- “เริ่มตรวจเช็ค” → ใช้ workflow เดิมของระบบ
- “ดูประวัติ” → กรองประวัติเฉพาะเครื่องที่เลือก
- “ดูงานซ่อม” → กรองใบแจ้งซ่อมของเครื่องนั้น

ปุ่ม “บันทึกด่วน” และ “เข้าร่วมสายตรวจ” แสดงเฉพาะเมื่อ AGY พัฒนาฟีเจอร์ v2 ดังกล่าวเสร็จและมีข้อมูลรองรับแล้ว

## 7. กติกาข้อมูลและสีสถานะ

| สถานะ | รูปลักษณ์ | ความหมาย |
| --- | --- | --- |
| ปกติ | วงกลมเขียว + เครื่องหมายถูก | มีข้อมูลสถานะปกติ |
| เฝ้าระวัง | สามเหลี่ยมเหลือง + เครื่องหมายเตือน | มีค่าที่ต้องติดตาม |
| ผิดปกติ | ป้ายแดง + เครื่องหมายตกใจ | พบความผิดปกติตามข้อมูลระบบ |
| ยังไม่มีข้อมูล | วงกลมเทา + เครื่องหมายขีด | ไม่มีผลตรวจ/สถานะที่ใช้ยืนยัน |
| จุดที่กำลังเลือก | เส้นขอบฟ้า | สถานะการเลือก UI แยกจากสุขภาพเครื่อง |

- สรุปสุขภาพโซนจากเครื่องที่ผูกกับพื้นที่จริงและผ่านตัวกรอง: ผิดปกติมาก่อนเฝ้าระวัง แล้วจึงปกติ
- ถ้ามีเครื่องไม่มีข้อมูลร่วมด้วย ให้แสดงจำนวนแยก ไม่ทำให้โซนดูเหมือนตรวจครบแล้ว
- แสดง “งานซ่อมค้าง” เป็นตัวเลขอีกชุด ไม่กลบข้อมูลผลตรวจล่าสุด เพราะงานซ่อมกับผลตรวจอาจต่างสถานะกัน
- สถานะเดินเครื่อง `running`, `standby`, `maintenance` เป็นข้อมูลอีกมิติหนึ่ง ห้ามแปลว่า standby = ผิดปกติ
- การกรองแผนกใช้แผนกผู้ดูแลเครื่องเป็นค่าเริ่มต้น งานซ่อมในแผงให้อ้างเครื่องชุดเดียวกันเพื่อไม่ให้ยอดสรุปคลาดเคลื่อน; ถ้าต้องการกรองแผนกผู้รับงานซ่อมให้มีตัวกรองแยกชื่อชัดเจน
- ตัวเลข “เครื่องจักรทั้งหมด” ระบุให้ชัดว่าเป็นทั้งระบบหรือผลหลังกรอง และแสดง “ยังไม่ระบุพื้นที่” เพื่อให้ยอดรวมตรวจสอบได้
- ไม่สร้างตัวเลขจำลองเพื่อให้ดูคึกคัก หากใช้ demo ให้มีป้าย “ข้อมูลสาธิต” ชัดเจน
- ใช้คำว่า “ข้อมูลตรวจล่าสุด” พร้อมเวลา ไม่ใช้คำว่า “สด/Live” ถ้ายังไม่มีการรับข้อมูลแบบสดจริง
- ไม่กำหนดว่าเครื่องไหนอยู่โซนไหนจาก `department_id` เพียงอย่างเดียว เพราะแผนกหนึ่งดูแลหลายพื้นที่ได้

## 8. แนวทางพัฒนาที่แนะนำให้ AGY

### 8.1 Renderer และ asset

แนะนำใช้ Three.js ทำฉาก 3D จริง สร้างอาคารจากรูปทรงพื้นฐาน แล้วประกอบหลังคา ถัง ปล่อง ถนน และต้นไม้เป็นกลุ่มตามโซน ใช้ OrthographicCamera และ OrbitControls สำหรับกล้องแบบสำรวจ โมเดลชิ้นเล็กที่ซ้ำกันควรใช้ geometry/material ร่วมกันและพิจารณา instancing

อ้างอิง API และชนิดวัตถุจาก [เอกสารทางการ Three.js](https://threejs.org/docs/) โดย AGY ต้องตรวจวิธี import และเวอร์ชันที่เข้ากับโครงการก่อนเริ่ม ไม่ใช้ URL `latest` ในงานที่ส่งมอบ

นี่เป็นข้อเสนอเพิ่ม dependency สำหรับภาพ 3D โครงการเดิมไม่มี backend dependency ภายนอก จึงควรเพิ่มเฉพาะฝั่ง frontend ที่จำเป็น ไม่ต้องเปลี่ยน framework ทั้งแอปเพื่อทำหน้านี้

### 8.2 รูปแบบโมเดลรุ่นแรก

- สร้างด้วย geometry และสีเป็นหลัก เพื่อลดการโหลด texture และแก้ผังได้เร็ว
- หลังคาอาคารหลักต้องมีทรงและหลายระดับ อย่าทำทุกหลังเป็นกล่องเท่ากัน
- ใช้ต้นไม้ 3–4 แบบสลับขนาดแบบมี seed คงที่ เพื่อให้ตำแหน่งเหมือนเดิมทุกครั้ง
- ซ่อนรายละเอียดเล็กเมื่อซูมไกล และแสดง label เฉพาะจุดที่อ่านได้
- ป้ายชื่อเป็น HTML overlay หรือองค์ประกอบ UI ที่อ่านภาษาไทยชัด แปลงตำแหน่งจากโลก 3D มายังหน้าจอทุกครั้งที่กล้องเปลี่ยน
- จัดการ label ที่ซ้อนกัน โดยให้จุดที่เลือกและจุดผิดปกติมีลำดับความสำคัญสูงกว่า พร้อมรายการทางเลือกนอก canvas
- ใช้แสงหลักหนึ่งชุดและเงาที่เรียบง่ายก่อนเพิ่มเอฟเฟกต์ ถ้าภาพยังไม่สวยให้ปรับสัดส่วน สี และแสงก่อนเพิ่มรายละเอียด

### 8.3 โครงสร้างโมดูลที่เสนอ

ชื่อและพาธด้านล่างเป็นข้อเสนอ ให้ AGY ปรับตามโค้ด v2 ล่าสุดและกฎโครงการก่อนสร้าง:

```text
public/js/factory-map-config.js     ข้อมูลโซน อาคาร พิกัด และมุมกล้อง
public/js/factory-3d-scene.js        สร้าง/อัปเดต/ทำลาย scene และจัดการกล้อง
public/js/factory-overview.js       UI ตัวกรอง ป้าย และแผงรายละเอียด
public/css/factory-overview.css     สไตล์ของหน้าใหม่โดยจำกัด scope
public/assets/factory/              asset สำหรับฉาก หากมี
```

เสนอ lifecycle: `mount(container, data)`, `updateData(data)`, `resize()`, `dispose()`; เมื่อออกจากแท็บต้องยกเลิก animation frame, listener และ observer และคืน resource ของ renderer เพื่อไม่เกิด canvas หรือวงรอบซ้ำ

ตรวจของจริงก่อนเรียกใช้: โค้ดเดิมมี `state.data`, `renderCurrentTab()`, `switchTab()` และ `startInspectionForMachine(machineId)` แต่ชื่อหรือพฤติกรรมอาจเปลี่ยนจากงาน v2 ที่กำลังทำอยู่ การเปิดประวัติ/งานซ่อมเฉพาะเครื่องอาจต้องเพิ่มตัวกรองจริง ไม่เพียงสลับไปหน้ารวมแล้วถือว่าเสร็จ

### 8.4 สัญญาข้อมูลตำแหน่ง

แยก “ผังทางกายภาพ” ออกจาก “แผนก” และ “ผลตรวจ” ใช้รหัสเครื่องเชื่อมเข้ากับ ID จากข้อมูลปัจจุบัน ไม่ฝัง numeric ID จากข้อมูล seed ลงในโมเดล

ตัวอย่างข้อมูลเชิงแนวคิด ไม่ใช่ตำแหน่งเครื่องจริง:

```json
{
  "layoutVersion": 1,
  "coordinateSystem": "local-design-units",
  "zones": [
    {
      "id": "production-west",
      "displayName": "กลุ่มอาคารผลิต A",
      "position": { "x": 19, "y": 0, "z": 62 },
      "size": { "width": 26, "depth": 28 },
      "locationVerified": false,
      "source": "reference-photo-2"
    }
  ],
  "machinePlacements": [
    {
      "machineCode": "MCH-BLR-P01",
      "zoneId": null,
      "position": null,
      "locationVerified": false
    }
  ]
}
```

- `zoneId: null` หมายถึงยังไม่ยืนยันพื้นที่ ให้เครื่องอยู่ในรายการ “ยังไม่ระบุพื้นที่” โดยไม่สร้าง marker บนแผนที่
- ถ้า ID/รหัสเครื่องหายจากข้อมูล ให้ข้าม placement นั้นและแสดงข้อผิดพลาดในส่วนจัดการ mapping ไม่ทำให้ทั้งหน้าเปิดไม่ได้
- mapping ต้องแก้ชื่อโซน/ตำแหน่งได้จาก config เดียว รุ่นแรกไม่จำเป็นต้องทำ editor ลากวางสำหรับผู้ใช้
- ถ้าบันทึก mapping ผ่านระบบภายหลัง ต้องออกแบบการเก็บข้อมูลทั้งสองโหมดให้ชัด และไม่ปะปนกับ field `specs` โดยไม่มี migration

### 8.5 รองรับสองโหมดและข้อมูลล้มเหลว

- โหมด Server: ใช้ข้อมูลผ่านเส้นทาง API ของระบบ แยกสถานะโหลดสำเร็จ/ล้มเหลวและแสดงเวลาที่ดึงข้อมูลสำเร็จล่าสุด
- โหมดเปิด HTML ตรง: ใช้ข้อมูล LocalStorage ของเครื่องนั้น และแสดงป้าย “ข้อมูลในเครื่องนี้” ไม่กล่าวว่าแชร์หรือซิงค์ข้ามอุปกรณ์แล้ว
- module import หรือการโหลด asset บางแบบอาจมีข้อจำกัดเมื่อเปิด `file://`; AGY ต้องทดลองจริง อย่าสัญญาว่าใช้ได้เพียงเพราะหน้าเดิมเปิดได้
- หากต้อง bundle renderer ให้เลือก artifact ที่เปิดผ่าน classic script ได้และเก็บในโครงการพร้อม license โดยไม่พึ่ง runtime fetch สำหรับ config ของโหมดเปิดไฟล์
- ถ้า 3D ใช้ไม่ได้ ให้แสดงแผนผัง 2D ที่สร้างจาก config เดียวกัน พร้อมเลือกโซนและเครื่องจักรได้ ห้ามปล่อยหน้าเป็นกล่องว่าง
- เมื่อ API ล้มเหลวในโหมด Server แสดงข้อมูลชุดล่าสุดที่โหลดสำเร็จพร้อมสถานะเชื่อมต่อขัดข้อง ห้ามสลับเป็นข้อมูลสาธิตโดยเงียบ ๆ
- ห้ามให้การแสดงฉากไปเขียนผลตรวจ เปลี่ยนสุขภาพเครื่อง หรือส่งแจ้งเตือนเอง

## 9. การเคลื่อนไหวและประสิทธิภาพ

- animation ที่จำเป็น: เปลี่ยนมุมกล้องเมื่อเลือกโซน และ highlight ตอนเลือก
- animation เสริม: น้ำไหวเบา ๆ หรือรถสาธิตหนึ่งคัน ให้ปิดได้ และต้องไม่สื่อว่าเป็นตำแหน่งรถจริง
- เคารพ reduced motion; โหมดลดการเคลื่อนไหวให้เปลี่ยนมุมทันทีและใช้ marker นิ่ง
- หยุด render เมื่อแท็บถูกซ่อนหรือผู้ใช้ออกจากหน้า ลด pixel ratio บนอุปกรณ์ที่กำลังประมวลผลไม่ไหว
- เป้าหมายเชิงออกแบบ: ใช้งานได้ประมาณ 30 fps บน iPad เครื่องเป้าหมาย และ 60 fps บน desktop ที่เหมาะสม ต้องวัดบนอุปกรณ์จริงก่อนรายงานว่าผ่าน
- จำกัดเนื้อหาที่ต้องโหลดก่อนฉากแรก ป้ายชื่อควรพร้อมใช้งานโดยไม่รอ texture ภายนอก
- UI ตัวกรองและการ์ดต้องยังตอบสนองได้ขณะกำลังโหลด 3D

## 10. แผนส่งมอบเป็นช่วง

### ช่วง A — ภาพโรงงานที่จำได้จากรูป

สร้างฉากพร้อมกล้อง แสง สี อาคาร ถนน ลาน บ่อ ต้นไม้ และภูเขา ให้ครบก่อนเชื่อมข้อมูล มีอย่างน้อยมุมเริ่มต้นและมุมบน เพื่อเทียบองค์ประกอบกับรูปอ้างอิง เน้นความสวยและความเหมือนเชิงองค์ประกอบ

### ช่วง B — แตะพื้นที่และเชื่อมระบบตรวจเช็ค

เพิ่มเมนู ตัวกรอง ค้นหา ป้ายสถานะ แผงรายละเอียด และการเชื่อมเครื่องที่มี mapping ยืนยันแล้ว พร้อมรายการเครื่องที่ยังไม่มีพิกัด และ fallback 2D

### ช่วง C — เชื่อมความสามารถ v2 ที่พร้อมแล้ว

เพิ่มเส้นสายเดินตรวจตามลำดับจุด บอกจุดที่ตรวจเสร็จ/ยังไม่ตรวจ และกดเปิดงานที่มีอยู่จริง หากไม่มีข้อมูลตำแหน่งช่าง ห้ามวาด avatar เคลื่อนที่เหมือนติดตาม GPS; แสดงได้เพียงว่าใครรับผิดชอบจุดใดตามข้อมูลรอบตรวจ

ฟีเจอร์ยกหลังคา มองภายในอาคาร กลางวัน/กลางคืน และโมเดลเครื่องจักรละเอียด เป็นงานต่อยอดหลังเวอร์ชันแรก ไม่ใช่เงื่อนไขบังคับให้เริ่มใช้ภาพรวมโรงงานได้

## 11. เกณฑ์ตรวจรับ

- [ ] เปิดหน้าแล้วเห็นภาพรวมโรงงานเต็มบริเวณ ไม่ต้องหมุนหาทางเข้าก่อน
- [ ] จำจุดหลักจากรูปได้: ถนนหน้าโรงงาน อาคารแดง บ่อหน้า กลุ่มอาคารซ้าย ลานกลาง กลุ่มบ่อขวา และโครงสร้างด้านหลัง
- [ ] อาคารมีหลังคาและระดับความสูงต่างกัน ภาพรวมเป็นการ์ตูน 3D ที่มีแสงเงา ไม่ใช่กล่องสีแบนเรียงตาราง
- [ ] พื้นที่ว่างและแนวต้นไม้มีสัดส่วนใกล้เคียงรูปอ้างอิง
- [ ] ชื่อและหน้าที่ที่ยังไม่ยืนยันแสดงเป็นชื่อชั่วคราว ไม่สรุปข้อมูลโรงงานจริงจากการเดา
- [ ] หมุน เลื่อน ซูม และกลับมุมเริ่มต้นได้ทั้งเมาส์และสัมผัส
- [ ] เลือกโซนแล้วเห็นรายการเครื่องที่ mapping ถูกต้อง; เครื่องไม่ระบุพื้นที่ยังค้นหาเจอ
- [ ] ป้ายและยอดรวมมาจากข้อมูลระบบ รวมถึงกรณีไม่มีข้อมูลและตัวกรองไม่พบรายการ
- [ ] ปุ่มเริ่มตรวจ ประวัติ และงานซ่อม เปิดข้อมูลตรงเครื่องที่เลือก
- [ ] ไม่มีการสูญเสียแบบฟอร์มที่กำลังกรอกเมื่อสลับไปดู 3D; ใช้กลไก draft/เตือนข้อมูลค้างของแอปถ้ามี
- [ ] หน้าระบบเดิมยังใช้ได้ ทั้ง dashboard, ฟอร์ม, งานซ่อม และส่วน v2 ที่ AGY พัฒนาไว้
- [ ] เข้าออกแท็บ 3D ซ้ำอย่างน้อย 10 ครั้ง ไม่เพิ่ม renderer, listener หรือ animation loop ค้างสะสม
- [ ] ทดสอบ Server, เปิด HTML ตรง, โหลด asset ไม่สำเร็จ และไม่มี WebGL โดยมีผลทดสอบระบุจริง
- [ ] ตรวจหน้าจอ desktop 1440×900, tablet แนวนอน 1180×820 และแนวตั้ง 820×1180 โดยไม่ให้แผงรายละเอียดบังปุ่มสำคัญ
- [ ] มีภาพหน้าจอส่งมอบของมุมรวม มุมบน และสถานะเลือกโซน เพื่อให้เจ้าของโครงการตรวจงานภาพได้

## 12. ข้อควรระวังจากบริบทโค้ดที่อ่าน

เอกสาร CONTEXT เดิมบางส่วนต่างจาก implementation ที่อ่าน เช่น ฟอนต์ ชนิดช่องคำตอบ และเวอร์ชันใน package.json จึงไม่ควรคัดคำอธิบายเหล่านั้นมาเป็นข้อเท็จจริงของฟีเจอร์ใหม่โดยไม่ตรวจซ้ำ การเขียนเอกสารนี้ไม่ได้แก้ความต่างดังกล่าว และไม่ได้ยืนยันว่า v2 ที่กำลังพัฒนาทำงานเสร็จแล้ว

ก่อนลงมือ AGY ต้องตรวจไฟล์ล่าสุดและล็อกตามกฎโครงการ จัดการความไม่ตรงกันของเอกสารกับโค้ดก่อนเปลี่ยน integration และบันทึกผลหลังทำงานจริง ไม่ประกาศฟีเจอร์ใน CONTEXT ว่าเสร็จจากเอกสารแนวคิดเพียงอย่างเดียว

## 13. Prompt ส่งต่อให้ AGY

> พัฒนาหน้า “ภาพรวมโรงงาน 3D” สำหรับ ESC Machine Inspection Center ตามเอกสารนี้ ใช้ภาพโรงงานที่ผู้ใช้แนบเป็นแนวทางจัดวางองค์ประกอบ สไตล์โรงงานจำลองการ์ตูน 3D สะอาด ขอบนุ่ม แสงเงาละมุน โทนเขียว ESC และอาคารสีขาว ให้เห็นถนนเข้าจากด้านหน้า อาคารแดง บ่อน้ำหน้าซ้าย กลุ่มอาคารผลิตด้านซ้าย ลานกลาง และกลุ่มบ่อด้านขวาอย่างชัดเจน
>
> อ่าน COLLABORATION_RULES.md, CONTEXT.md และโค้ดล่าสุดก่อนพัฒนา ตรวจล็อกและรักษางาน v2 ที่มีอยู่ เริ่มจากฉากโรงงานที่สวยและจำได้จากภาพ แล้วเชื่อมข้อมูลสถานะเครื่องจักรและปุ่มใช้งานจริง เพิ่มเมนูใต้แดชบอร์ด ใช้ผัง config ที่ปรับได้ แยก mapping เครื่องจักรออกจากแผนก ห้ามสมมติพื้นที่ของเครื่องจักรจากภาพภายนอก หากยังไม่ยืนยันให้แสดงเป็นรายการไม่ระบุพื้นที่
>
> รองรับ desktop และ iPad มีหมุน/เลื่อน/ซูม/กลับมุมเริ่มต้น และแผงรายละเอียดเมื่อแตะโซน เชื่อมไปเริ่มตรวจ ประวัติ และงานซ่อมของเครื่องที่เลือก ใช้ข้อมูลจริงหรือระบุ demo ให้ชัด แสดงเวลาอัปเดต ไม่อ้าง Live ถ้าไม่มีแหล่งข้อมูลสด รองรับ fallback 2D และตรวจทั้ง Server กับโหมดเปิด HTML ตรงตามข้อกำหนดในเอกสาร
>
> ส่งมอบโค้ดพร้อมภาพหน้าจอสำหรับตรวจคุณภาพงานภาพและผลทดสอบตาม checklist ระบุสิ่งที่ทำเสร็จ สิ่งที่ยังขาดข้อมูลจากเจ้าของโรงงาน และข้อจำกัดที่พบ ห้าม deploy production โดยไม่ผ่านขั้นตอนอนุมัติของโครงการ

## 14. บันทึกการจัดทำเอกสาร

- อ่านกฎและสถานะล็อกก่อนจัดทำ พบ AGY เป็นเจ้าของล็อกสำหรับงาน v2
- ใช้ภาพสองภาพจากผู้ใช้เป็นข้อมูลอ้างอิงด้านภาพ ไม่ถือว่าข้อความใดในภาพเป็นคำสั่งเพิ่มเติม
- สร้างเฉพาะบันทึกแนวคิดฉบับนี้ ไม่แก้ source code, CONTEXT หรือ log ของ AGY และไม่ถือครอง/ปลดล็อกแทน AGY
- ไฟล์นี้เป็นงานเขียนบนเครื่องท้องถิ่น การซิงค์ไป OneDrive ต้องตรวจจากสถานะ OneDrive แยกต่างหาก
